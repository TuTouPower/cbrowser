# d055 固定 146 引擎自由模式可用开发者模式加载解压目录，CRX3 需提取公钥保持 ID，Bitwarden Passkey 代理链路可行

- 来源：`docs/spikes/s029_extensions_and_bitwarden_passkey/`（`s029` 正式 spike，2026-11-22，容器镜像 `cbrowser-browser:2d93270-IDrqH2` / `chromium-146.0.7680.177.3` `ungoogled-chromium`）。 [Spike 报告](../spikes/s029_extensions_and_bitwarden_passkey/report.md)
- 结论：
    1. `cloakbrowser` `0.6.4` 的 `launch_persistent_context_async` 硬编码 `ignore_default_args=IGNORE_DEFAULT_ARGS`（仅移除 `--enable-automation` 与 `--enable-unsafe-swiftshader`），导致 Playwright 1.64.1 无条件注入 `--disable-extensions` 与 `--disable-component-extensions-with-background-pages`。唯有直接接管 Playwright `ignore_default_args` 并显式加入 `--disable-extensions`（自由模式/受管开启态）或保留之（关闭态），才可控制扩展子系统真实启停；且关闭态必须同时省去 `--load-extension` 与 `--disable-extensions-except` 才能使存量已安装扩展静默（内容脚本与 Service Worker 均不执行）。
    2. 自由模式（移除 `--disable-extensions` 且不传 `--load-extension` / `--disable-extensions-except`）实测三个候选入口：Chrome Web Store 在线页面仍横幅提示 `Switch to Chrome to install extensions and themes` 且 `Add to Chrome` 按钮保持 `disabled: true`；`file://` 与合成 `DataTransfer` drop 本地 `.crx` 只触发下载或无安装反应；**唯一可用入口为开启 `chrome://extensions` 开发者模式后点击 `Load unpacked` 经 GTK3 文件选择框加载解压目录**，且加载后的扩展在同一持久化 `user_data_dir` 重启后持久生效，切回关闭态彻底停用，切入受管模式（`--disable-extensions-except`）时被拒绝执行。
    3. 解压加载的扩展 ID 连续性：Chromium 对缺少 `manifest.key` 的解压目录按规范路径哈希计算 `chrome.runtime.id`（实测路径由 `v1` 变为 `v2` 后无 `key` 扩展 ID 从 `ooeeofcnhjbcbnoilllhmjfoaooiomae` 变为 `gckbbgbcjebjkhckmndolcegjdimcafe` 并丢失原 `chrome.storage.local` 键 `probeToken`）；带有效 RSA 公钥 `key` 的扩展跨路径保持 `knbohljdmgknocmlihddnkkmcigcnnab` 不变且存储连续；官方 Chrome Web Store 下载的 `bitwarden.crx`（`2026.11.0`，CRX3）内部 `manifest.json` 默认无 `key` 字段，且 CRX3 头含多条 RSA 证明（发行商轮换密钥），解包时须按 `SignedHeaderData.crx_id` 精确匹配对应 `sha256_with_rsa` 公钥写入受管目录 `manifest.json["key"]`，才可在任意受管挂载路径下保持官方 ID `nngceckbapebfimnlniiiahkandclblb` 连续。
    4. 官方 Bitwarden MV3 扩展（`2026.11.0`，`nngceckbapebfimnlniiiahkandclblb`）在受管模式与另 1 个受管 MV3 扩展并发加载下 Service Worker 与弹窗正常；通过本地 HTTP CONNECT 代理（`vault.s029.local:8443`、无宿主直连 DNS）完成 `Vaultwarden 1.37.5` 自托管登录与 `/api/sync` 同步后，对 HTTPS RP 页面 `https://rp.s029.local:8443/webauthn` 真实拦截 `navigator.credentials.create()`（弹窗「Save passkey as new login」，保存加密 cipher 并返回 `ok: true`、`attestationLen: 178`）与 `navigator.credentials.get()`（选择 Passkey 完成签名并返回 `ok: true`、`authDataLen: 37`、`sigLen: 72`、`userHandle: "AQIDBAUGBwg"`），全部网络请求经 Profile 代理通道无直连绕过。
