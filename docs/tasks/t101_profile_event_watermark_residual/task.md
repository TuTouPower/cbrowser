# Task spec

## 背景

t098 两轮代码审阅留下两条 minor 残余（review_code Round 2 的 `t098_code_f003` / `t098_code_f004`），登记为 p158。t098 为事件同步加的「新鲜度门」只以 per-profile runtime 缓存为唯一见证：该缓存仅在详情访问时填充，列表/会话常驻路径通常为空，此时陈旧与重复事件仍触发集合页与 alerts 的多余重取；见证存在时也只压住严格更旧的事件，同 revision 重复事件在成员分支无去重。此外，抑制生效时成员行跨越筛选边界会落入就地写回分支，把已跨出筛选桶的行仍写回筛选页且总数不变，直到一次无关重取才收敛。两者均为有界的多余请求或单行暂时不一致，无状态倒退、无数据丢失，故 t098 定级 minor、不阻断 PASS，单独留待修复。

## 契约区

### 范围

- 前端事件同步增加 per-profile「已见最高 revision」水位，作为集合页非成员失效、alerts 失效与重复事件的统一见证。水位取自 runtime 缓存与全部集合缓存行中该环境的最大 `state_revision`，并在处理事件后记录当前已见最大值，跨缓存失效仍保留。
- 低于水位的历史事件、与水位相等且投影相同的重复事件，均不触发集合页与 alerts 失效。字段合并仍按各缓存自身 revision 围栏进行。
- 被抑制的事件命中成员行、且合并后状态跨越当前筛选边界时，该行保持原样不动，不写回筛选页、不改动总数；状态与成员关系继续由服务端收敛。

### 非范围

- 后端集合读模型、SSE 事件形状与 revision 语义调整。
- 共享 revision 围栏 `runtimeFenceAllows`、投影相等 `projectionsEqual` 与落地合并 `mergeFetchedCollectionItems` 的既有语义改动。
- 管理界面配色、策略或部署流程调整。

- 风险：统一水位取自有界集合页，跨筛选页的水位汇总需遍历全部集合缓存；水位记录与缓存解绑后可能残留偏高的修订，令后续同修订新事件被误抑制。
