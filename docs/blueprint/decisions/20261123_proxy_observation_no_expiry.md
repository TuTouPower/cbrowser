# 042 代理观测快照取消 TTL（2026-11-23，t105）

- 背景：ADR 029 为出口观测设定了 24 小时 TTL，理由是「出口位置会漂移」。实际运行中 `expires_at = datetime.now() + 86400` 完全由 API 自己填写，并非探测返回的数据；它把出口 IP、国家、城市与测速延迟绑在同一条快照上，到点整条作废，`observation_status` 回落 `unknown`，UI 显示「未测速」。同时 `failed` 行无过期时间、永久可见，同一个观测元组出现两套时效规则。用户 2026-11-23 反馈「重启后测速结果没了」，现场 84 条最新 `ok` 中 77 条已过期，4 条 `failed` 仍可见，与截图吻合。
- 选项：
    1. 保留 TTL，增加周期巡检/唤醒调度，到期自动重测：结果会回来，但需要全新的常驻调度子系统与预算/失败收敛规则，只为让本不该消失的数据重新出现。
    2. 把测速延迟从 Geo 观测中拆开、分别设时效：违反「出口地理与测速结果属于同一元组、同生共死」的领域定义。
    3. 取消 TTL，快照永久有效，只在端点或凭据变化时失效并重测（本 ADR 采用）：直接删除时间维度，无需任何调度机制。
- 结论：采用选项 3，替代 ADR 029 中 TTL 24 小时与「过期自动重新探测」的口径（该口径在 blueprint/spec 中本就未收敛，代码也未实现）。
    - **领域规则**：出口 IP、国家、城市与 `latency_ms` 是同一条观测快照，同生共死。观测只追加历史行；当前观测 = 最新一行且端点指纹与凭据版本匹配当前端点，`ok` 另需出口 IP 与国家码。`ok` / `failed` / `pending` 三类状态统一适用该身份规则，无时间条件。
    - **破坏性删除**：移除 `OBSERVATION_TTL_SECONDS`、`EgressObservation.expires_at`、`ProxyResponse.expires_at` 与 ORM 列；迁移 0018（`b2c3d4e5f601`）删除 `proxy_egress_observations.expires_at`，只进不退，不做兼容保留或反向迁移。
    - **读模型**：`proxy_country_ranges` 与 `list_proxies_page` 共用「最新行」口径，先按每代理最新行排序再判 `status == "ok"` 且国家码非空，避免旧 `ok` 地理与列表展示漂移。
    - **后果**：出口 IP/地理随时间漂移时不再自动刷新，只有端点/凭据变化或用户手动测速才产生新观测。该能力按当前单机单人需求不需要；若以后需要，应作为独立的产品决定重新设计，而不是恢复一个人为的 24 小时常量。
